## Пользовательская модель

- Новая доверенная регистрация: автоматически создаётся производный «Личный».
  Его адрес отличается от корневого; сеть запускается после выбора контекста.
- Дополнительный профиль: любое непустое название до 80 символов. Это обычный
  двусторонний адрес с отдельной историей, ником и настройками ноды/связи.
- Выбор в шапке определяет фактического отправителя. Онлайн только один профиль.
  Неактивные профили не получают сообщения в фоне; их ноды могут иметь очереди.
- Название профиля локальное; публичный ник задаётся отдельно.
- Доступно до 255 внешних профилей, включая архивные. Переименование не меняет
  адрес. Архивирование не удаляет историю; текущий профиль сначала переключают.
- Одна seed контролирует все профили, это не изоляция от владельца seed и
  не обещание анонимности. IP и другие метаданные могут связывать адреса.

## Что отключено

`PROFILE_FEATURES.advancedInbox = false` — неизменяемая политика сборки,
не URL-параметр, не настройка localStorage и не разрешение пользователя.
Технический main-профиль остаётся в реестре для совместимости формата, но не
предлагается как адрес общения. Общий просмотр, чтение других профилей,
шаблоны Входящие/Исходящие и подтверждения подключений отсутствуют в обычном UI.
Их реализация и отдельные тесты остаются для будущего этапа.

Важно: флаг останавливает вызовы чтения общего снимка при входе/переключении,
а не только прячет блоки. Запрос общего вида и переключение на технический main
отклоняются. Новая регистрация и добавление произвольного профиля не создают
никаких cross-profile grants. Старые права остаются в файле, но не используются.
Один профиль не пересылает и не показывает переписку другого автоматически.

## Существующие данные и восстановление

Существующие аккаунты не переписываются. Если реестра нет, явное включение
профилей оставляет текущий адрес «Личным», чтобы не потерять старые чаты.
Ранее сохранённый выбор технического агрегатора переводится на обычный профиль.
Неверный/архивный выбор остаётся fail-closed: сеть не публикует корень в качестве
автоматического запасного адреса; пользователь выбирает профиль в шапке.

Импорт зашифрованного списка проверяет принадлежность адресов seed и восстанавливает
список/имена/индексы, но не историю и не старые разрешения. Следует обновлять
резервный файл после создания профилей. Только seed не содержит их имён/индексов;
seed-only восстановление пока сохраняет прежний сценарий существующего аккаунта.
Временная недоверенная сессия не сохраняет реестр профилей.

Формат реестра не изменён. Обычный режим больше не создаёт бессрочных grants,
поэтому не вносит прежнюю несовместимость с 0.1.6 для новых реестров. Если
бессрочные contributions уже были созданы в прошлой локальной рабочей итерации,
они сохраняются: старый клиент их не прочитает. Откат серверных файлов не откатывает
браузерную БД, её нельзя очищать ради отката. Перед возвратом такого реестра в
старый клиент нужен отдельный совместимый экспорт/преобразование.

## Проверка на телефонах после публикации

1. Оба устройства: `https://automesh.space/` → Настройки → Приложение →
   Проверить обновления → Обновить приложение. Проверить номер 0.1.7.
   Данные сайта не очищать; существующая домашняя нода 0.1.2 не меняется.
2. Для проверки нового сценария использовать отдельный браузерный профиль/
   устройство без ценного аккаунта: новая доверенная регистрация должна открыть
   «Личный» без ручного создания связки. Seed настоящих аккаунтов не отправлять.
3. Настройки → Аккаунт → Профили → пароль → Добавить профиль: любое название.
   Выбрать его в шапке: адрес должен отличаться, старые чаты не подмешиваются.
4. Переключиться обратно: адрес и история «Личного» сохранились. Повторить
   блокировку/разблокировку и перезапуск приложения с выбранным вторым профилем.
5. Другой телефон добавляет конкретный адрес выбранного профиля; проверить
   обычную переписку в обе стороны. Для второго адреса нужен отдельный контакт.
   Настройки ноды/ключи очереди не копируются между профилями автоматически.
6. Обновить резервный зашифрованный файл со списком профилей. На отдельном
   тестовом устройстве импортировать его и проверить те же адреса и названия.
   Импорт списка не переносит историю чатов.
7. В обычном UI не должно быть общего ящика, специальных шаблонов или
   подтверждений доступа. Одновременный приём нескольких адресов не ожидается.
