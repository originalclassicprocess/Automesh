# UI polish — 0.3.7

This patch changes presentation/navigation, not routing, encryption, grants,
node state, message persistence or transfer scheduling.

## File activity

Each conversation row and open chat shows independent upload/download badges
with counts and byte-weighted progress. Waiting uploads count; unaccepted file
offers do not pretend to be active downloads. Completion removes the badge.
An interrupted transfer retains an explicit error marker. A direct upload at
100% remains visible until the receiver confirms saving: browser-buffered bytes
are not a safe handoff. Node storage means
upload completion, not delivery to the recipient. Incoming completion waits
for verification/local-save state, not just a byte counter reaching 100%.
Percentages describe current unfinished files; completing/removing one changes
the denominator. Badges never accept files, start network work or send ACKs.

## Waiting messages

Compact chat-list labels distinguish key exchange, missing/disabled/unreachable
nodes, denied rights, timeouts, quotas and pending local sends. The open-chat
label expands to a bounded explanation. Only allowlisted reasons are used,
never raw errors. A later incoming reply does not hide an older pending send.
Completed/node-stored messages, imported archives and routine sent status are
excluded. Files still show explicit key/access failure reasons, separately
from their progress counter.

## Navigation

The contact QR scanner reuses a styled image-picker component rather than
exposing the native file input. Camera, image selection and close controls
share the application palette and reflow within the actual sidebar width.
Image validation and scan cancellation remain unchanged.

The settings Back button follows node task → nodes → connection overview →
settings menu → the previous non-settings view. Media details follow their
own overview. Parent selection works even if the user jumped between tabs;
it does not replay every visited sibling. Discarded Forward snapshots are
normalized. Other Back handling, exit guards and account-session clearing
are retained.

## Theme contract

Settings → Application offers system/light/dark. System mode follows OS media
queries; an explicit choice wins. Only a non-sensitive device-wide preference
is stored, not account metadata. A same-origin CSP-compatible prepaint script
restores it before rendering; unavailable storage falls back safely.

Shared semantic colors cover the shell, chat bubbles, settings, forms, status
indicators, dialogs and calls. New components must use those tokens and shared
controls; a regression test rejects new literal component colors. The viewer
stays deliberately dark, video frames remain neutral, and QR/avatar/media pixels
are not inverted or changed by the theme. This is a maintainable default, not
a guarantee that arbitrary future hardcoded styling can adapt automatically.

## Local verification

986 app/server tests passed across 163 files, including activity projections,
pending-message reasons, hierarchy transitions and semantic color/contrast
checks. Component types reported zero errors/warnings; core TypeScript passed.

An isolated browser scenario checked real settings navigation after repeatedly
switching sections, theme persistence after reload/unlock, automatic OS theme
changes, and 320/390/1920px layouts without overflow or page errors. Separate
390/1920px fixture screenshots were inspected in light and dark themes. The
fixtures contain only synthetic state and do not touch real user accounts.
The contact scanner was additionally checked at 320/390/600/1920px, including
image selection without a valid QR, error display and close/cancellation. Its
390/600px screenshots were inspected after the shared picker refactor.

The final production build, production-server checks, PWA precache/offline
checks and internal release gate passed (323 production sources, 95 unchanged
canonical node files and unchanged Windows/Linux package checksums). Existing
large-bundle and browser-crypto compatibility build warnings remain visible.

Physical phone testing and publication are not part of these local checks.
