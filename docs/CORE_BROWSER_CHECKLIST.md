# Проверка нового хранилища в настоящих браузерах

Дата: 2026-10-04. Чекпоинт 0.1.4 перед профилями опубликован на домене:
`v0.1.4-7402b1379dac614b`. Мобильная проверка пользователем ещё ожидается.
Цель: проверить WebCrypto/IndexedDB вне fake-indexeddb до подключения профилей.
Работа старых аккаунтов и ноды не меняется. Seed и пароль пользователя не нужны.

## ПК

Открыть https://automesh.space/diagnostics/core
в обычном браузере. Версия страницы должна начинаться с `v0.1.4-`.
Локально: `npm run dev` → `http://localhost:5173/diagnostics/core`.
На странице есть пошаговая инструкция. Вход в настоящий аккаунт не нужен.

1. «Подготовить»: создаёт вымышленные данные в отдельной базе прогона.
2. Перезагрузить страницу, нажать «Проверить сохранение» — результат «ПРОШЛО».
3. Закрыть страницу и открыть **ту же ссылку с run=…** в течение часа.
   Повторить «Проверить сохранение», не нажимая заново «Подготовить».
4. «Открыть вторую тестовую вкладку» → там «Проверить сохранение».
5. Нажать «Гонка вкладок» в обеих вкладках: только одна сообщает «принята»,
   другая — «повтор отклонён». Подготовка сбрасывает гонку для нового прогона.
6. «Проверить сбои»: конкуренция, закрытие, имитация сброса и повреждение.
   Все четыре проверки должны завершиться «ПРОШЛО».

Сброс имитируется только для тестового адаптера: глобальная эпоха приложения
не меняется. Проверка не трогает сейф, историю, настройки, сертификаты и ноду.
Все обращения драйвера перенаправлены в базу `automesh-core-browser-check-v1-<run>`.
Повреждение и очистка касаются только этой базы. Тестовая идентичность общеизвестна;
это не аккаунт для переписки. После проверки сбоев тестовая база пустая.

Проверено 2026-10-04 в браузере Codex на ПК (Chromium): сохранение после reload,
гонка двух настоящих вкладок, закрытие, имитированный сброс, повреждение.
Это не проверка Safari, Android, отключения питания или исчерпания диска.

## Android и iPhone/Safari — ещё не проверено

Открыть https://automesh.space/diagnostics/core в обычном Safari на iPhone
и обычном браузере Android. Локальный сервер на ПК, сертификат LAN и нода
для этой проверки не нужны. Устройства проверяют своё локальное хранилище:
IndexedDB не синхронизируется между ПК и телефоном.

Выполнить те же шаги. Для теста перезапуска закрыть вкладку и снова открыть сохранённую
ссылку с run=…, не восстанавливать настоящий аккаунт.
Safari обычный режим и приватный режим — разные условия; основной прогон
проводить в обычном режиме. Ошибку/невозможность сохранения не считать успехом.

Сообщить: устройство, браузер/версия, обычный или приватный режим, пройденный
шаг и текст ошибки. Не присылать личные seed, пароли, бэкапы и ключи.
Страница `/dev/core` и остальные страницы разработки закрыты в production.
Опубликована только изолированная `/diagnostics/core`; результатов на сервере нет.

После теста обновить обычную PWA: Настройки → Приложение → Проверить обновления
→ Обновить приложение. Проверить разблокировку и обмен сообщениями как раньше.
Не очищать данные браузера и не переустанавливать ноду. При сбое сохранить текст
ошибки и остановить переход к профилям. Серверный релиз можно откатить штатным
`rollback`; это не откат данных браузера, но в 0.1.4 миграций аккаунтов нет.

## Переход к профилям

После браузерного чекпоинта — отдельная итерация реестра/миграций:
фиксированные тестовые векторы дочерних ключей, зашифрованный локальный реестр,
сохранение старого ID и расширенный бэкап с индексами. Затем переключение в UI
и следующий небольшой деплой. Не соединять миграцию seed, смену транспорта и
большую переделку интерфейса в одном релизе.
