# Чистый запуск на новом хостинге · 0.4.0 / нода 0.4.5

Пакеты подготовлены локально. Эта инструкция не меняет DNS, хостинг и старую
установку. Пользовательские данные, ключи и очереди НЕ включены. Развёртывание
выполняется оператором отдельно. Информационный сайт в этот пакет не входит.

| Роль | Адрес | cPanel |
| --- | --- | --- |
| Мессенджер + сигналинг + подключение устройств | https://automesh.online | отдельное Node.js app |
| Нода + панель + её сигналинг | https://automesh.space | отдельное Node.js app |

Публичные значения по умолчанию: `nodes/packages/deployment/src/defaults.js`.
В мессенджере контактные ссылки используют origin реально открытого приложения,
сигналинг по умолчанию — его `/signal`. Другой домен не требует пересборки.
`ORIGIN` задаётся при запуске, разрешения ноды — через `allowedOrigins`.
Нода не подключается автоматически и не получает seed. Информационный сайт
пока отключён (`projectOrigin: ''`): домен для него не выбран и не требуется.
Не покупать и не подключать дополнительные домены ради запуска мессенджера.

## Сначала — подготовка в cPanel (вручную, не выполнена)

1. Добавить два домена и отдельные document roots; не использовать общий каталог.
   Для ноды выбрать `/home/USER/automesh.space` (ожидается мастером ниже).
   Сохранить чужие MX/TXT и другие DNS-записи, если они есть.
2. Подключить DNS и получить действующие HTTPS-сертификаты средствами хостинга.
   Включить HTTP→HTTPS, сохранив ACME/pki-validation. Не отключать проверку TLS.
3. Подготовить Node.js >=22.12 (поддерживаемый 24.x предпочтителен), SSH/Terminal.
   В каждом приложении production, один worker; проверить фактическое поведение
   LiteSpeed. Несколько workers не заменяют масштабирование общего реестра.
4. Проверить WSS и работу после простоя. Shared-хостинг может остановить процесс;
   очередь сохраняется на диске, но выключенная нода не доставляет сообщения.
   Ни тариф, ни успешный HTTP-ответ не подтверждают круглосуточную доставку.

## Мессенджер — пакет `Automesh-App-0.4.0-clean.tar.gz`

- Распаковать в новый application root `/home/USER/automesh-app`, не в каталог
  ноды. Архив имеет верхний каталог:
  его содержимое должно стать корнем приложения, без лишнего уровня вложенности.
- Setup Node.js App: URL `https://automesh.online`, startup `app.cjs`, production.
- Env: `NODE_ENV=production`, `ORIGIN=https://automesh.online`. HOST/PORT оставить
  управлению хостинга. Пример `.env.example` не загружать как реальный секретный env.
- Выполнить `npm ci --omit=dev --ignore-scripts` в Node environment приложения.
  Затем запустить/перезапустить средствами cPanel.
- `/healthz`, `/_app/version.json`, WSS `/signal` должны работать; `/dev` — 404.
  HTML/worker/version.json не кэшировать в прокси, immutable-ресурсы можно.

## Нода — пакет `Automesh-Node-0.4.5-shared-clean.tar.gz`

Это готовые исходники/production-зависимости под **Passenger/LiteSpeed**, не
Linux-VPS runner. Не запускать `adapters/server/main.js start` как замену.
TLS завершается хостингом; адаптер проверяет приватный Unix listener. Собственный
самоподписанный сертификат и открытие служебного TCP-порта не нужны.

1. Распаковать в новый `/home/USER/automesh-node-app`. Архив содержит файлы в корне.
   `USER` — реальный cPanel user, не буквальный текст и не системная переменная HOME.
2. В Node environment этого приложения, **только для нового пустого запуска**:

   ```sh
   node scripts/verify-shared-package.mjs
   node scripts/setup-shared-host.mjs /home/USER https://automesh.space /home/USER/automesh.space 39304 https://automesh.online
   ```

   Мастер создаст `.automesh-node-private` с новым master key и config и отдельный
   `.automesh-node-data` с новой идентичностью/пустыми очередями. Всё вне публичных
   папок; ключи не печатаются. Существующие ключи не перезаписываются. При ошибке
   проверить частично созданные файлы, не удалять их и не запускать вслепую заново.
3. Setup Node.js App: URL `https://automesh.space`, root `automesh-node-app`,
   startup `app.cjs`, production; env
   `AUTOMESH_NODE_CONFIG=/home/USER/.automesh-node-private/config.json`.
4. Запустить через cPanel (не обычный запуск `node app.cjs` поверх TCP).
5. Через SSH выполнить:

   ```sh
   node scripts/check-shared-host.mjs https://automesh.space https://automesh.online
   node adapters/passenger/main.js admin-setup /home/USER/.automesh-node-private/config.json
   ```

   Первая команда проверяет HTTPS/CORS/подписанную WSS-регистрацию без привязки
   постоянного аккаунта или записи сообщений. Вторая выдаёт секретный одноразовый
   код назначения администратора: использовать локально, не публиковать в Git/чате.
   Затем войти в панель и подтвердить новым аккаунтом на `.online`.
6. Привязать свежие тестовые аккаунты через приглашения панели. Пользователь
   сам выбирает ноду; адреса/права старой ноды не считаются действительными.

Ключи создавать только на целевом хостинге. Сохранить отдельно шифрованную копию
private config/master key и data directory. Разделение папок внутри одного
cPanel не изолирует их от другого приложения того же Unix пользователя.

## Старые браузеры и PWA

`.online` — другое browser origin: старые данные `.space` туда не переедут.
Автоматического удаления/импорта/перенаправления аккаунтов в пакете нет.
Старая PWA/service worker `.space` может показывать кэш мессенджера вместо панели
ноды. Перед тестом панели отключить старый service worker этого сайта или открыть
чистый профиль браузера. Не посылать глобальный Clear-Site-Data и не удалять
пользовательское хранилище автоматически.

## Приёмка и ограничения

Проверить два свежих аккаунта: прямой текст/файл в обе стороны, офлайн-доставку с
закрытым отправителем, основное+подключённое устройство, перезапуск ноды с очередью,
посторонний Origin (403), отсутствие публичных ключей/конфигов, версии/хеши.
Проверить домашнюю Windows/Linux-ноду с новым `.online` и отдельную LAN-связь.
Новые ноды используют `.online` по умолчанию; старые конфиги не переписываются.

Сборки локальные, без независимой подписи или GitHub attestation. SHA-256
подтверждает совпадение файлов, не безопасность кода. Архивы не включают DNS,
действующие TLS-сертификаты, cPanel credentials, аккаунты или очереди.
