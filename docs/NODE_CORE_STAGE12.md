# Ноды: этапы 1 и 2 — 2026-10-09

Статус: реализованы локально; сайт, сервер и GitHub не обновлялись.
Проект нод 0.3.0, протоколы v1 и seed/MAE не изменены.

## Надёжность и управление

- Добавлено управление восемью привязками в Windows UI: выбрать профиль →
  отключить с подтверждением. Очищаются только очереди/файлы этого профиля
  на ноде. Аккаунт и клиентские чаты остаются. Уже доставленные копии не удаляются.
- Отзыв сохраняется до удаления; после сбоя cleanup возобновляется до запуска
  listeners/routes. Старые proofs не возвращают членство. Очистка освобождает
  слот; код привязки надо создать заново. Публичный LAN-сигналинг не блокируется.
- Ящики не смешиваются после удаления первого профиля: исходная директория
  фиксируется `primaryAddress`, новый owner использует собственный ящик.
- Исходящие счётчики/файлы из `/outbox/status` изолированы по профилям;
  администратору доступен общий статус и список очередей.
- HTTP-операции и courier-акторы сериализованы общей очередью. Закрытие ждёт
  операции и загрузки частей. Просроченные файлы очищаются и без подключения.
- Удаления синхронизируются с диском на POSIX. Отказ записи авторизационного
  состояния блокирует дальнейшее обслуживание до безопасного перезапуска.
- Для защиты секретов ядро требует явный адаптер. Windows DPAPI находится
  только в Windows-оболочке; plaintext/тестового production fallback нет.
- Добавлены тесты повторов/ACK, рестартов, cleanup при сбое, квот, malformed
  proofs, отсутствующих частей, удаления/перепривязки и изоляции профилей.

## Отдельный проект

`nodes/packages/protocol`: чистый JS wire contract + адреса/proofs.
`nodes/packages/runtime`: Node.js-ядро без зависимостей от UI/seed приложения.
`nodes/adapters/windows`: UI/установщик/TLS/DPAPI/LAN.

У проекта собственные package/lockfile, MIT, third-party notices, документация,
20 встроенных автотестов и CI для Windows/Linux/macOS. CI настроен в исходниках,
но ещё не запускался на GitHub; кроссплатформенные результаты не заявляются.
Windows-сборка самостоятельна; клиент/сервер пока используют тонкие локальные
экспорты в `nodes/`, без второй реализации. Упаковка сайта включает только
необходимый сигналинг/протокол/лицензию, не node control и очереди.

Подготовлен отдельный локальный Git-репозиторий:
`<independent-checkout>/automesh-nodes`.
Первый коммит `a5c92d1`, ветка `codex/node-core`, remote отсутствует.
`docs/ORIGIN.md` сохраняет происхождение; полная история остаётся в приложении.
`npm run node:export` создаёт новый allowlisted source snapshot с SHA-256
manifest. Не экспортирует пользовательские данные, конфиги, ключи и .git.

До выбора GitHub/package delivery переходная исходная копия в `nodes/` остаётся
в приложении. Отдельный репозиторий — зафиксированный самостоятельный снимок,
не второе место параллельного редактирования. Следующий этап выберет canonical
remote и закреплённую зависимость клиента. Не делать ручные расходящиеся копии.

- Сборка приложения и локальные production/PWA-проверки прошли.

  Windows-установщик независимо от репозитория приложения. Его исходники
  зафиксированы; generated outputs/зависимости не попали в Git.

  ошибка реального деплоя: никаких запросов к хостингу не выполнялось.

Установщик остаётся unsigned preview. Проверки не являются независимым
криптоаудитом и не обещают защиту от compromised OS/browser/server.
