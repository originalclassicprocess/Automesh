# Проверка интерфейса 0.0.3

Статус: опубликовано на automesh.space 2026-10-02, сборка `v0.0.3-4c8046e3ac569d7c`.
234 автоматических теста и проверки production/PWA прошли; HTTPS и WSS проверены.
Браузерная камера, реальный микрофон и компоновка на телефоне требуют ручной
проверки. Автотесты не заменяют проверку кодеков на Safari/iPhone и Android.

## Запуск

В каталоге проекта: `npm run local:pwa` (готовая сборка на http://localhost:5173/).
Для связи нужен отдельный `npm run signaling`. Если порты заняты прежними
серверами, сначала остановите именно их. Для LAN используйте прежний `npm run lan:pwa`.
В production-PWA: «Настройки → Приложение → Проверить обновления → Обновить приложение».
Каждую вкладку/PWA обновите отдельно. Доверенный вход и история сохраняются;
недоверенную временную историю перед обновлением сохраните переходом в доверенный режим.

## Два тестовых аккаунта

- В поле поиска введите ник — список фильтруется. Введите полный mesh1… —
  появляется «＋»; Enter/кнопка открывают чат. Собственный ID не принимается.
- «▦» → камера или изображение из галереи: QR карточки второго аккаунта
  открывает его чат. QR сервера, прямого offer/answer и URL не принимаются.
  Чтение QR происходит локально и не подтверждает личность само по себе.
- Примите первый запрос. У неизвестного/заблокированного контакта вложения
  и запись аудио недоступны.
- Индикаторы: Интернет/LAN — доступность настроенных серверов подключения,
  не общий тест интернет-сети. P2P — число открытых каналов с собеседниками.
  При отключении сигналинга сохранённый прямой канал может остаться зелёным.
- При ширине 390 px и на ПК проверьте отсутствие горизонтального скролла,
  видимость кнопок, высоту истории и переход «←» к списку.
  Сохранена прежняя логика: переход к первому непрочитанному, отметки только
  для реально видимых сообщений; увеличенная область покажет больше сообщений.
- «📎»: выберите 3 изображения; все появляются отдельными сообщениями
  со своими статусами. Примите файлы у получателя, сравните изображения.
  Проверьте отказ для файла >20 МБ и очереди >16 файлов.
- «🎙»: разрешите микрофон, запишите речь, «■ ↗» завершает и отправляет запись.
  «✕» отменяет без отправки. У принятого контакта аудио до 5 МБ принимается
  автоматически: дождитесь передачи, нажмите Play прямо в чате, без «Скачать».
  Автовоспроизведения нет. При исчерпании лимита автоприёма 20 МБ на сеанс
  следующие записи принимаются вручную. Большие аудиофайлы тоже вручную.
- Запись → смените чат/откройте настройки/заблокируйте аккаунт/скройте вкладку:
  индикатор микрофона браузера должен погаснуть, незавершённая запись не уходит.
  При отказе в доступе — понятная ошибка, текст и вложения продолжают работать.
- В Chrome и Safari проверьте взаимное воспроизведение. Формат выбирает браузер
  из MP4/WebM/OGG; если кодек получателем не поддерживается, показана ошибка
  плеера и остаётся скачивание, перекодирование пока не реализовано.
- Своя аватарка: карточка с ID/QR и выходом; второе нажатие закрывает её.
  «🔒» возле настроек сразу блокирует аккаунт, история сохраняется по прежней политике.
- Настройки → Приложение: начинается проверка обновлений, показывается
  актуальная версия/наличие новой копии/ошибка сети. Проверка не перезагружает
  вкладку; применение остаётся отдельным действием.

Фоновые проверки обращаются только к собственному сайту, в видимой вкладке,
при запуске, восстановлении online-события и раз в 15 минут. Это не сканирование LAN.
