# Квота ноды и освобождение доставленных копий — 0.4.5 / нода 0.4.10

Лимиты файлов профиля (16 по умолчанию), файлов всей ноды (128) и общего зарезервированного объёма независимы. Их значения не меняются этим выпуском. Соединение с нодой не подтверждает наличие свободной квоты. Облако показывает только нодную очередь, размеры отдельных файлов и локального хранилища туда не входят.

`/outbox/status` возвращает агрегат `automesh-queue-quota-v1`: собственные файловые слоты/лимит, общие слоты/лимит, общий занятый или зарезервированный объём/лимит. Доступ — действующий подписанный запрос участника. Агрегат не раскрывает чужие адреса и сообщения. В интерфейсе показаны время проверки и устаревание после 45 секунд; неизвестная квота не считается свободной. При исчерпании любого лимита красное облако имеет приоритет над зелёным состоянием сохранённых конвертов.

Счётчик «На ноде» берётся из ответа ноды по текущему профилю. Внутри отдельно указано количество из истории этого устройства. Оно может быть меньше после другого сеанса, удаления истории или восстановления резервной копии. Старая подпись «Очередь доступна · ожидают N» заменена, чтобы не смешивать связь, локальную очередь и квоту.

Исправлена утечка файловых слотов: раньше успешная прямая доставка удаляла pending-запись клиента, но сама по себе не была квитанцией для нодного шифротекста. Теперь клиент освобождает такую копию существующим авторским подписанным запросом отмены, сохраняя локальную запись для повторной попытки до ответа ноды. История остаётся в состоянии «доставлено», а не «отменено». Для файла недостаточно подтверждения метаданных — требуется fileStatus=ready. Приём по ноде использует прежнюю подписанную квитанцию получателя.

Для исправления старых потерянных pending-записей добавлен `/outbox/list` (`automesh-outbox-inventory-v1`): только собственные исходные подписанные задания, страницы до 8/384 КБ, без потребления конвертов. Неполные загрузки тоже учитываются. Клиент проверяет подпись автора, адрес ноды и принадлежность задания, затем сопоставляет с собственной историей. Неизвестные сообщения, восстановленные/импортированные записи и файлы без полного подтверждения не удаляются автоматически. Общей административной очистки нет.

Сверка и освобождение выполняются отдельно от основной очереди: задержка/ошибка перечня или отмены не задерживает отправку, не меняет её backoff и не создаёт ложной квитанции. До двух освобождений за проход. Новые попытки, ключи, сроки хранения, маршруты и доставка между нодами не менялись. Старые клиенты сохраняют прежнюю доставку; новая квота/восстановление старых копий требуют обновлённой ноды.

Проверено: разделение профильного и общего лимитов, закрытый HTTP-доступ, постраничная выдача только своих заданий, фоновая сверка без задержки poll, повтор после сбоя отмены, сохранение неизвестных/неполученных копий и уже доставленной истории. Личные сообщения в боевой среде проверяет владелец проекта.
