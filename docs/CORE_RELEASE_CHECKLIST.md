# Проверка релиза 0.1.3

Все участники открывают **https://automesh.space/** или установленную с него
PWA. Не переходить на localhost/LAN-страницу: у другого origin другой сейф.
Новый установщик ноды не требуется; её протокол и права не менялись.

## До начала

1. Сохранить имеющуюся резервную копию аккаунта. Не очищать данные браузера.
2. Дождаться завершения отправок/сохранения и убрать несохранённые черновики.
3. Настройки → Приложение → Проверить обновления → Обновить приложение.
   Сделать на обоих участниках; версия должна начинаться с **v0.1.3-**.
   Другие открытые вкладки не обновляются принудительно.

## Обычная работа: ПК, Android, iPhone

1. Разблокировать старый аккаунт: прежние ID, контакты, история и вложения на месте.
2. Три раза заблокировать/разблокировать без перезагрузки; неверный пароль
   должен отклоняться, верный открывает тот же аккаунт.
3. Два разных аккаунта онлайн: отправить текст в обе стороны, ответ на
   сообщение, контакт, картинку/файл и аудио. Проверить доставку и просмотр.
4. Отключить/вернуть связь и отправить новый текст. При ожидании не должно
   появляться ложное «Доставлено»; после получения не должно быть дубликатов.
5. По возможности проверить разные сети (домашний Wi-Fi ↔ мобильная сеть).
   Без TURN отдельные NAT/VPN по-прежнему могут не позволить прямое соединение.
6. QR и известный домашний сигналинг должны работать как раньше. Новые
   разрешения API не заменяют сертификаты/привязку установленной ноды.

## Исходящая нода

1. Оставить установленную рабочую ноду запущенной, проверить индикатор.
2. Два доверенных клиента после обновления соединить онлайн, чтобы заранее
   обменяться одноразовыми ключами. Получателю отдельная нода не нужна.
3. Закрыть получателя; отправить три пронумерованных текста. Дождаться
   «Сохранено на узле», а не просто «Ожидает отправки».
4. Закрыть отправителя, открыть получателя: приходят три текста ровно по разу.
   Получатель должен быть доступен ноде через рабочий сервер подключения.
5. Открыть отправителя: подтверждения должны обновиться после проверки квитанций.
   Если запас одноразовых ключей закончился, это причина ожидания, не потеря текста.

## PWA и восстановление

1. После загрузки обновления проверить офлайн-готовность, закрыть PWA и
   открыть без интернета: приложение открывается, старый архив доступен.
   Это не гарантия связи без транспорта или фоновой работы закрытой PWA.
2. На отдельном тестовом профиле браузера восстановить тестовый аккаунт
   из старого зашифрованного файла; не перезаписывать основной аккаунт.
3. Старая вкладка не должна терять данные из-за обновления другой вкладки.
   Не держать несколько разблокированных экземпляров одного аккаунта ради теста.

## Что пока не появится в интерфейсе

HTTP API, новые профили, роли плагинов, страницы/группы и долговечная защита
операций от повторов не включены. Новый API проверяется автотестами; этот
чеклист проверяет совместимость реально подключённой границы чата.

При проблеме сообщить: версия, устройство/браузер, маршрут (интернет/LAN/QR/нода),
действия и точный текст ошибки. **Не отправлять seed, пароль, закрытые ключи,
резервные файлы или одноразовые коды привязки.** Не удалять хранилище для «починки».
