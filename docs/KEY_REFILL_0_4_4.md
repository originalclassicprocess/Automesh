# Пополнение ключей и компактная шапка — 0.4.4 / нода 0.4.9

Причина: при повторной публикации клиент считал закрытые приёмные ключи, которые ещё должны храниться для конвертов в пути, снова доступными для новых отправлений. Собеседник уже пометил их использованными, поэтому повтор того же набора не увеличивал остаток. Дополнительно ↻ отображал только возможность запроса к ноде, не подтверждая реальный запас.

В подписанном зашифрованном обмене появились необязательные consumedKeys (не больше 32 идентификаторов предыдущего набора) и requestKeys. Владелец помечает только собственные прямые ключи этого собеседника как retired, сохраняет закрытые части до окончания срока приёма и больше их не рекламирует. При остатке не больше пяти дополняет набор до 32. Ответ отправляется после завершения обработки входящего сообщения, чтобы двусторонние обработчики не блокировали друг друга. Ответы ограничены по частоте и прекращаются при блокировке клиента. Подпись проверяется до изменения состояния.

CourierState v3 сохраняет retired. Старые читатели v2 должны отклонять его: иначе они снова рекламировали бы отработанные ключи. Откат клиента после записи v3 — только вместе с прежним подходящим состоянием; сид, идентичность и шифрование истории не меняются. Исторические закрытые ключи не передаются собеседнику или ноде.

Новый read-only запрос к ноде собеседника показывает реальный остаток опубликованных ключей. Доступ ограничен ключами именно запрашивающего собеседника. Число внизу чата — сумма доступных локальных ключей и последнего подтверждённого нодой запаса; подробности разделяют оба числа и показывают время проверки. Просмотр счётчика не расходует ключ. Неизвестный запас обозначается ?, недоступный — !, подтверждённый пустой — 0. Снимок устаревает за 45 секунд. Прямой канал для этой проверки не требуется.

Запрос счётчика работает отдельно от очереди отправки, с отдельной защитой от параллельных запросов. Потерянный/задержавшийся ответ не блокирует сообщения. Ответ, полученный после расходования ключа этим клиентом, не перезаписывает свежий счётчик. Владельцу нужно оставить основной клиент открытым для пополнения каталога; приватные ключи нода сама не создаёт.

В шапке одно облако 44×44: серый — пусто/передача ноде, зелёный — сохранено на ноде, красный — отмена/истечение/ошибка. Непустые состояния переключаются каждые 3,5 секунды; при reduced motion остаётся приоритетное состояние. Точные подписи доступны в подсказке и окне подробностей. Облако учитывает только взаимодействие с нодой, без размеров файлов, локального хранилища и обычной прямой очереди. Окно сначала показывает компактные категории со счётчиками; список чатов и действия раскрываются по нажатию. Уведомления об остановке можно скрыть в одном чате или во всех, не удаляя сообщения. Мобильный и широкий примеры используют тот же AccountHeader.

Проверки: настоящий зашифрованный чат с запасами 0/0 и 0/17, сохранение возможности расшифровать конверт до обновления набора; HTTP-проверка доступности без расходования и без раскрытия чужого запаса; пополнение через ноду при незавершённом P2P; задержка счётчика без задержки доставки; узкая шапка 320 px и широкая 1406 px с доступными настройками.
