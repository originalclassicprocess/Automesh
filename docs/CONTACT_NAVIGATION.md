# Карточки и навигация

Текущий релиз 0.0.8 опубликован: `v0.0.8-4b3b94eb0c1f44e9`.
Обязательные проверки CI и автоматическая проверка установки прошли успешно
(запуск 37052695644). «Поделиться» опубликовано ранее в 0.0.7;
эта часть тогда не тестировалась локально по просьбе пользователя.

## Что изменено

### Мобильная адаптация 0.0.8

Escape на компьютере проходит внутреннюю историю, но не закрывает вкладку.
Android Back/свайп и обычный жест Safari Back обрабатываются через `popstate`.
Они используют те же переходы, что стрелки интерфейса, включая экраны до входа.
Открытые панели сначала закрываются. Снимки не содержат seed/пароли и не могут
вернуть уже очищенную учётную запись. Во время критических асинхронных операций
возврат удерживает текущий экран. Корень предупреждает первым Back, следующий
быстрый Back отдаётся браузеру; после 2 секунд барьер восстанавливается.

Мобильный viewport не запрещает масштабирование. Ввод на сенсорном устройстве
имеет размер 16px; контейнер ограничен экраном, учитывает клавиатуру и safe-area,
использует внутреннюю прокрутку вместо прокрутки документа/pull-to-refresh.
`overscroll-behavior` уменьшает обновление от прокрутки там, где браузер его
поддерживает, но не даёт права управлять системным закрытием браузера/жестами ОС.

Новый аккаунт всегда создаётся с 12 словами. Селектор длины существует только
при восстановлении, одинаково на всех платформах. Другой экран/старая PWA-сборка
могут выглядеть иначе; обновление проверяется в «Настройки → Приложение».

Ручной чек-лист на настоящем телефоне после обновления:

- Портрет/альбом, ширина 320–430px: нет горизонтальной прокрутки; Account ID,
  QR, карточки и кнопки помещаются, поля не запускают автоматический zoom.
- Вход → восстановление → пароль: системное Back возвращает, отменённые seed
  и пароль не появляются при Forward. Ник/пароль с клавиатурой доступны.
- Чат → карточка → настройки/подраздел → Back: предыдущий экран, не закрытие.
- Галерея, пересылка, удаление, QR-сканер, резервная копия: Back/Escape закрывают
  открытый слой. Подтверждение не выполняет удаление при нажатии Back.
- Список → Back: подсказка и приложение остаётся; пауза >2s → снова один Back
  оставляет приложение; два быстрых Back могут уйти со страницы. Escape не уходит.
- Прокрутка истории не обновляет страницу; клавиатура не перекрывает отправку,
  поворот/ручной zoom доступны. Сравнить Safari-вкладку и установленную PWA.

### Возможности 0.0.7

- В открытом аккаунте сохраняем переходы: чат/список, карточка, раздел настроек,
  подраздел связи и галерея. Кнопка «Назад» проходит предыдущие состояния,
  не сбрасывает всё сразу к главному экрану. На корневом списке первое нажатие
  остаётся в приложении с подсказкой; следующий выход контролирует браузер/ОС.
  Это не гарантированное закрытие браузера и не выход из аккаунта. История
  настройки/авторизации до входа в 0.0.7 ещё не была включена; в 0.0.8 добавлена.
- Используем shallow routing SvelteKit, не обходим его history API. В браузерную
  историю записываются только непрозрачные session/index, не Account ID, файлы,
  пароли или seed. Снимки интерфейса в памяти сбрасываются при блокировке/выходе;
  старая запись истории не разблокирует аккаунт. История прежних браузерных
  сеансов/особенности установленной PWA не дают гарантии «ровно два нажатия».
- ContactCard — отдельный компонент для собственного и чужого аккаунта.
  Account ID, копирование и QR. Public key убран **только из чужой карточки**:
  проверка подписей/Account ID и локально известные ключи не изменены.
- Локальное имя меняется через кнопку «Переименовать»; объявленный ник виден
  независимо от локального имени. Собственный ник редактируется в настройках.
- Пока только 1-на-1: кнопка личного чата, а не вымышленный список общих групп.
  Новому контакту можно начать чат, но принятие/блокировку не обходим.
- Вложения этого диалога: все/фото/видео/аудио/файлы, сначала новые, порциями.
  Удалённые вложения скрыты. Неполученные видны как метаданные с отметкой.
  Фото/видео загружают локальное превью по видимости, после проверки размера и
  SHA-256; активные SVG/HTML не отображаем. Аудио/обычные файлы имеют пиктограмму.
  Видео в карточке без автопроигрывания. Кнопка вложения открывает исходный чат
  и подсвечивает сообщение; принятие, скачивание и плеер доступны уже в чате.
- В собственной карточке вложения только из «Сохранённых», не из всех контактов.

## Проверки

Для 0.0.8: `check` без ошибок/предупреждений, 295 тестов, сборка, PWA-shell и
production-проверки успешны. В изолированной вкладке localhost:5188 проверены
свежий старт, восстановление → Escape → старт, затем корневой Escape с подсказкой
без ухода со страницы. Реальные аккаунты не открывали/не изменяли. Браузерная
проверка выявила и помогла исправить ранний вызов history до готовности роутера
и чтение устаревшего page.state: используем сам payload события popstate.
Диагностические атрибуты готовности/позиции есть только в dev-сборке, без секретов.
Узкий viewport не заменяет Safari/Android и не подтверждает системные жесты ОС.

Предыдущие проверки 0.0.7:

Модульные: предыдущие страницы, корневой барьер без ловушки Back, очистка после
закрытия аккаунта, отсутствие приватных снимков в history, категории, порядок и
исключение удалённых/активных форматов. Полный набор — 289 тестов.

Изолированный браузерный origin 127.0.0.1:5188: возврат встроенными кнопками через
history.back между карточкой и разделами настроек, переименование, копирование,
категории, переход/подсветка сообщения TXT, миниатюра публичной тестовой PNG в
«Сохранённых». Не затрагивали реальные аккаунты, не отправляли внешним контактам.
Системный Back на Android/iOS и выход из установленной PWA требуют ручной проверки.

## «Поделиться»: реализованный вариант

Основной вариант — https://automesh.space/#/contact/<Account ID>. Контакт в самой
ссылке, без базы коротких ссылок/токенов на сервере. Фрагмент не входит в HTTP-
запрос страницы, но доступен её JavaScript; хостинг видит посещение/IP, внешний
мессенджер видит пересылаемую ссылку. Это не анонимность и не скрытие от клиента.

Клиент валидирует Account ID, сохраняет только намерение открытия контакта до
завершения входа/создания аккаунта, затем показывает карточку/диалог. Запрос
отправляется только после явного «Написать», не по открытию ссылки или её превью.
Ник из ссылки не подтверждает личность; адрес проверяется обычным протоколом.

Альтернативы: специальная URI automesh:… (нужен обработчик/установленный клиент)
или чистый Account ID/QR для импорта в любой экземпляр приложения. Один адрес
контакта не является WebRTC-предложением и не создаёт сетевой путь: при отсутствии
сигналинга понадобится прямой обмен QR соединения. Для первого скачивания клиента
без офлайн-копии нужен доступ к источнику приложения.

Web Share при поддержке/разрешённой политике вызывается по нажатию. Без поддержки
— явное копирование/выделение ссылки; отмена системного меню ничего не копирует
и не отправляет. В ссылку не включаем seed, ключи, IP/узлы, локальный псевдоним.
