# Automesh: переносимое ядро v1

Дата: 2026-10-04. Это первая изолированная итерация ядра платформы, а не
завершение всей дорожной карты. Включено в релиз приложения 0.1.3;
протокол сервера/узла и форматы сохранённых аккаунтов не изменены.

Дополнение 0.1.4: реализованы долговечные зашифрованные повторы
и политика отзыва. Опубликован релиз с отдельной браузерной проверкой на домене;
в обычные чаты новое хранилище ещё не подключено. Детали — `CORE_DURABLE_STATE.md`.

## Что является ядром

`src/lib/core/index.ts` — публичная точка входа. Ядро использует контракты
`IdentityProvider`, `CoreEnvironment`, `ReplayStore` и `PolicyStore`, общие Account ID и
формат транспортного конверта. Оно не импортирует Svelte, DOM-страницу,
браузерное хранилище, конкретный транспорт или HTTP-клиент. Время, генерация
ID, криптография, подписант и хранилище повторов передаются зависимостями.
`tsconfig.core.json` проверяет эту границу без конфигурации SvelteKit.

```text
UI / доверенный контроллер приложения
    │ внутренний API v1
    ▼
core: проверка конвертов / подписанные объекты / разрешения / повторы
    ├── IdentityProvider + Account ID
    ├── CoreEnvironment: WebCrypto, время, ID
    ├── ReplayStore: атомарное занятие идентификатора операции
    └── PolicyStore: доверенные эпохи/отзывы/свежесть политики

Отдельно: SecureSessions (E2EE), transport, vault/history, node HTTP-adapter.
```

Проверка существующих входящих конвертов подключена к ChatService. Новый
формат объектов и разрешений доступен через API, но не заменяет автоматически
форматы сообщений, почты, привязку нод или пользовательские права в UI.

## Характеристики и фактическое состояние

| Характеристика | Реализовано в этой итерации / уже было | Следующий отдельный этап |
| --- | --- | --- |
| Стабильная идентичность | Прежняя деривация P-256/Account ID, фиксированные векторы, неизвлекаемый закрытый CryptoKey | Производные профили и зашифрованный реестр с восстановлением |
| Аутентичность | Проверка подписи, привязки ключа к автору и получателя; копии данных до асинхронной проверки | Подключение новых объектов к конкретным модулям |
| Версионирование | API v1, объект v1 с отдельным контекстом подписи, старый конверт v2 без изменения байтов | Миграции реестра профилей/полных бэкапов |
| Минимальные права | Подписанный grant; теперь отдельно реализован зашифрованный адаптер политики, эпох и отзывов | Применение этих прав нодами и доставка обновлений политики |
| Защита от повторов | Атомарный ReplayStore; дополнительно долговечный CAS-адаптер с защитой конкурирующих вкладок | Транзакция с прикладным эффектом, защита от полного отката базы |
| Ограниченность входа | Размер, вложенность, число элементов, строгие поля/типы, срок действия, отказ при неизвестной версии | Квоты источников/адресатов в сетевых адаптерах |
| Жизненный цикл | `close()` закрывает API, блокирует поздние результаты и последующее подписание | Полный профильный lifecycle и его интеграция с UI |
| Переносимость | Независимая компиляция, явные порты, нет скрытого сетевого/дискового ввода-вывода | Десктоп/мобильные адаптеры и отдельная упаковка библиотеки |
| Контролируемая расширяемость | Типы message/post/document/task/grant/revocation, единый доверенный API | Схемы содержимого модулей, изолированное исполнение, HTTP API |

Публичная точка входа не является границей безопасности для произвольного
JavaScript в том же процессе/origin. Стороннему модулю нельзя передавать
подписывающий API целиком. Нужны посредник, проверка полномочий и изоляция.
Здесь нет загрузчика плагинов, выполнения task или произвольного кода.

## Подписанный объект

Оболочка имеет ровно три поля: `record`, `publicKey`, `signature`.

`record` имеет ровно восемь полей:

- `version: 1`;
- `id`: UUID в нижнем регистре;
- `kind`: один из объявленных видов;
- `author`: Account ID подписанта;
- `createdAt`: целое неотрицательное безопасное число миллисекунд Unix;
- `expiresAt`: такое же число, строго больше createdAt/текущего времени, либо null;
- `audience`: до 64 различных корректных Account ID;
- `body`: ограниченное JSON-значение, схема которого принадлежит модулю.

Пустая audience не разрешает исполнение операции любому человеку. Она может
обозначать публичный объект для будущего модуля; `acceptOnce` требует явно
указанного получателя в audience. Подтверждение подписи не валидирует бизнес-схему
body (кроме grant в `authorize`) и не разрешает запуск кода из body.

Подписываемые байты: UTF-8 от `Automesh signed object v1`, затем байт NUL,
затем канонический JSON record. Подпись ECDSA/P-256/SHA-256, 64 байта P1363
(r || s); signature — 128 строчных hex-символов. publicKey — 65 байт raw
uncompressed P-256 (`04…`), 130 строчных hex-символов. Account ID вычисляется
по прежнему алгоритму. Новый контекст не совпадает с подписью конверта чата.

Automesh JSON v1 — собственная фиксированная схема, **не RFC 8785**:
ключи сортируются сравнением UTF-16 JavaScript; строки и конечные числа
кодируются JSON.stringify, `-0` становится `0`. Нормализации Unicode нет.
Запрещены undefined, bigint, NaN/Infinity, циклы, sparse arrays, accessors,
неперечислимые/символьные свойства, непростые прототипы и ключи
`__proto__`, `prototype`, `constructor`. toJSON не вызывается.
Для другой языковой реализации нужны соответствующие векторы, а не обычное
«отсортировать JSON». Новую схему нельзя вводить под старой версией.

Максимум: **64 KiB UTF-8 для всей оболочки**, 4096 посещённых JSON-значений,
глубина 16 (корень — 0), ключ объекта до 256 UTF-16 единиц. Значит доступный
размер body меньше 64 KiB. Полная оболочка проверяется до вызова подписи.
Файлы должны передаваться частями/по ссылкам, не в одном таком объекте.

Часы считаются доверенной зависимостью. Допустимое опережение createdAt —
5 минут; окончательная проверка срока повторяется после криптографии.
Неверные часы или их откат требуют обработки на уровне платформы.

**Подписанный body не зашифрован.** Подпись подтверждает автора и целостность,
но не обеспечивает секретность. Нельзя отправлять приватный объект в публичное
хранилище без отдельного шифрования. Текущее E2EE чата остаётся в SecureSessions;
проверка конверта выполняется до расшифровки и не принимает открытый текст как
замену защищённой сессии.

## Разрешения

grant привязан к одному субъекту и одному точному ресурсу вида `document:123`.
Разрешённые действия: `read`, `write`, `publish`, `deliver`, `execute`.
Wildcards и передача права другому субъекту запрещены; canDelegate только false.
notBefore/expiresAt задают окно, epoch — доверенную локальную эпоху политики.

Приложение, которому принадлежит ресурс, предоставляет ожидаемого issuer,
subject, resource, action и epoch. Их нельзя брать из заявления посетителя.
`authorize` проверяет подпись, вид объекта, все ограничения и свежий статус
отзыва. Только результат `false` от isRevoked допускает действие; неизвестный
статус, ошибка, отзыв или истечение срока означают отказ. Решение не кэшируется
ядром и действительно только на момент проверки, не на бессрочную сессию.

Подписанный объект revocation сам по себе не обновляет хранилище отзыва.
Новый `applyRevocation` проверяет подписанта/ожидаемый ресурс и передаёт
обновление отдельному долговечному адаптеру с порядком sequence/epoch.
Распространение отзыва остаётся задачей контроллера. Без свежей политики полностью
отключённому клиенту нельзя обещать мгновенный отзыв. Старые права нод ещё
не переведены на этот формат.

## Повторы и надёжность

`acceptOnce` проверяет автора, вид, получателя, подпись и конечный срок не
дальше 7 дней от проверки; затем атомарно занимает ключ
`[recipient, author, kind, id]`. Повтор с другой корректной ECDSA-подписью того
же объекта тоже считается повтором. Оно **не проверяет полномочие execute**:
для разрешённой операции отдельно требуются authorize и схема body.

MemoryReplayStore имеет явную ёмкость (по умолчанию 1024): заполнение даёт
ошибку, а не удаляет действующие отметки. Это защитная квота, не ограничение
количества сообщений чата или запаса prekeys. Просроченные записи очищаются.
Хранилище в памяти не защищает после перезапуска и не синхронизирует разные
вкладки/процессы. Нельзя использовать его для долговечных финансовых действий.

Порт ReplayStore требует атомарного claim. Read-then-write недостаточно.
Занятие claim и прикладной эффект пока не связаны одной транзакцией: сбой
между ними может потерять выполнение. Это не гарантия exactly-once. Для
бизнес-процессов нужна транзакционная очередь/idempotency на стороне эффекта.
Откат часов/восстановление старого snapshot хранилища тоже требует отдельной
защиты: долговечный адаптер сохраняет максимум времени, но не выявляет полный
откат всей базы. Для текущей MAE-сессии остаются прежние счётчики кадров; её повторы
не заменены этим новым API.

`close` не может отменить уже выполняемую операцию WebCrypto, но не выдаёт
результат закрытого экземпляра. IdentityProvider принадлежит контроллеру:
при блокировке он отдельно вызывает dispose, закрывает транспорт, останавливает
записи и очищает свои временные буферы. Ядро не хранит seed, но JS не гарантирует
физического стирания памяти. Утечка seed по-прежнему компрометирует идентичность.

## Проверки и оставшиеся риски

Команды: `npm run check:core`, `npm run check`, `npm run test:core`, `npm test`,
`npm run build`. Тесты включают подмену метаданных/получателя/подписи, домены,
неизвестную версию, сроки, размер/сложность, accessors, асинхронное изменение
входа, закрытие, неверные разрешения, отказ проверки отзыва и конкурентные повторы.
Проверки старых ключей, восстановления, MAE, почты и курьера остаются в регрессии.

Это внутреннее ревью и автотесты, **не независимый криптографический аудит**.
Не решены этой итерацией: права старого локального CA, широкие системные
firewall-правила, сетевые квоты по источнику/адресату, лимиты неизвестных RTC-пиров,
защита от вредоносной сборки/XSS, восстановление после кражи seed, защита от
отката/удаления всей базы повторов, полная изоляция профилей/модулей и HTTP API.

Следующая последовательность после локального адаптера: контракт
зашифрованного реестра профилей/миграций (PROFILES_PRIVACY_CONTRACT.md) → профили → ограниченный модульный
адаптер → отдельный сетевой API. Карты, группы, кошельки и автоматизации не
вводятся одной этой оболочкой. Общая дорожная карта остаётся в
`ROADMAP_IDENTITIES_NETWORK_MAPS.md`.
