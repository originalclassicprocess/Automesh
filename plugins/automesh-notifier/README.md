# Automesh Notifications 0.2.0

Локальный Windows-плагин для Codex: дублирует финальный ответ в личный чат
Automesh. Отдельный отправитель, один заранее выбранный получатель, текущий
подписанный E2EE-протокол приложения. Готового REST API в Automesh 0.1.4 нет:
плагин использует скомпилированные ChatService/WebRTCTransport в отдельном
headless-браузере. Развёртывание сайта и смена протокола не требуются.

## Подготовка

Нужны Windows, Node.js 20+ и Codex CLI в PATH, а также Edge или Chrome.
Все следующие команды выполняются из каталога плагина:

```powershell
node server/install.mjs --recipient <свой-публичный-Account-ID> --auto
node server/cli.mjs probe
node server/cli.mjs test
```

`--auto` включает согласие на автоматическое копирование финальных ответов
в настроенный чат. Команда без `--auto` отключает автоматическую отправку;
ручной MCP-инструмент остаётся доступен. По умолчанию `--browser auto` ищет
Edge, затем Chrome, затем Playwright Chromium. `--browser chrome` выбирает Chrome.
`--browser chromium` требует отдельно установить Chromium через Playwright.
`--app-url` по умолчанию `https://automesh.space/`; HTTP разрешён только loopback.
Другие ноды и произвольные URL отправки через MCP не принимаются.

Seed генерируется на машине и шифруется Windows DPAPI CurrentUser. Основной
аккаунт пользователя, его seed и браузерный сейф не используются. Конфигурация,
`sender.dpapi`, зашифрованная очередь и lock находятся в
`%LOCALAPPDATA%\AutomeshNotifier`. При желании общий каталог задаётся через
`AUTOMESH_NOTIFIER_DATA_DIR` для setup, MCP и hook одинаково.
Seed не печатается, не входит в параметры инструментов и не включается в ZIP.
DPAPI привязывает данные к Windows-пользователю: копирования каталога на другой
ПК недостаточно для восстановления. Для этого первого варианта перенос seed
не реализован; потеря защищённого файла требует нового отправителя.

Установщик размещает пакет Playwright в пользовательском каталоге
`%LOCALAPPDATA%\AutomeshNotifier\runtime`. Плагин работает из кеша Codex и
не зависит от исходного пути к проекту. На каждом ПК используется собственный
каталог данных, получатель и seed. Обновление сохраняет существующий seed.
Старая настройка `playwrightDirectory` версии 0.1.0 поддерживается; при новой
установке абсолютный путь в конфигурацию не записывается. Для разработчиков
остаётся необязательный `--playwright-dir <каталог-пакета-playwright>`.

Для ручной подготовки вместо установщика: `npm ci --ignore-scripts`, затем
`node server/setup.mjs --recipient <свой-публичный-Account-ID> --auto`.
В этом режиме runtime находится в исходном каталоге, который не следует удалять.

## Подключение к Codex

В репозитории добавлен каталог плагинов **MeshAutonomy Local**:
`.agents/plugins/marketplace.json`, запись `automesh-notifier`.
Установить его через каталог плагинов Codex, либо CLI:

```powershell
# Из корня клонированного репозитория:
codex plugin marketplace add .
codex plugin add automesh-notifier@mesh-autonomy-local
```

Перезапустить/обновить Codex, выбрать плагин и проверить
`get_notification_status` в новом чате. Перед автоматической отправкой
**просмотреть и доверить hook Stop в интерфейсе Codex**. Установка сама по себе
не даёт доверия hooks; плагин не меняет записи доверия и не обходит этот шаг.
Уведомления действуют в тех локальных чатах, где плагин включён и hook доверен.
В обычном ChatGPT и в облачной оркестрации локальный hook не исполняется.

## Передача другому пользователю

Готовый ZIP содержит один автономный каталог `automesh-notifier`, браузерные
сборки и собственный `.agents/plugins/marketplace.json`. Другой пользователь
распаковывает ZIP, открывает терминал в этом каталоге и выполняет приведённый
выше `server/install.mjs` со **своим** публичным Account ID. Полный проект
MeshAutonomy и твои данные ему не нужны. Каждый отдельно включает `--auto`
и доверяет hook в Codex.

В репозиторий и ZIP не входят локальная конфигурация, sender seed, очередь,
Windows-учётные данные и npm-зависимости. Стандартный адрес automesh.space
можно заменить через `--app-url`; это настройка, а не привязка к владельцу.
Пакет поддерживает **Automesh на Windows**. Другие мессенджеры и macOS/Linux
этим релизом не заявлены: сейчас хранилище секретов использует Windows DPAPI.
Передача ZIP или установка из GitHub не означает публикацию в каталоге OpenAI.

Hook `Stop` получает `last_assistant_message`, не читает весь transcript, файлы
или внутренние рассуждения. Он сообщает **«Ответ Codex завершён»**: это включает
вопросы и незавершённые задачи, а не автоматическую проверку успешного результата.
Первые 12 000 символов ответа, общий заголовок и ссылка на чат отправляются
получателю. Это явное копирование содержимого финального ответа; вложения не
копируются. Фоновый hook не блокирует и не продолжает работу Codex.
Если другой Stop hook продолжит этот turn, ранний ответ уже может быть скопирован;
повторный вызов нашего hook с тем же turn ID подавляется.

## Инструменты

| Инструмент | Действие |
| --- | --- |
| `get_notification_status` | Публичные IDs, настройка автоматизации, размер очереди; без отправки |
| `notify_task_completed` | Результат задачи с явным статусом и стабильным eventId |
| `flush_notifications` | Одна попытка отправить старейшую запись очереди |

У `notify_task_completed` поля `eventId`, `title`, `summary`, `status` обязательны;
`threadId` необязателен. Статусы: `completed`, `failed`, `needs_input`, `finished`.
Адрес назначения всегда берётся из локальной настройки, не из аргументов GPT.
Инструментов чтения чужих чатов, исполнения команд, получения seed и
произвольного browser eval нет.

## Доставка и ограничения

- `delivered` означает полученную аутентифицированную квитанцию ChatService.
  Это не подтверждение прочтения пользователем.
- `queued` означает сохранённую зашифрованную запись, доставка не подтверждена.
  Получатель должен быть онлайн; поддержка автономной доставки через его
  курьерскую ноду ещё не подключена в этом плагине.
- MCP-процесс повторяет одну запись каждые 45 секунд, пока он запущен. После
  закрытия Codex очередь остаётся на ПК. Новые hooks, следующий запуск MCP или
  `node server/cli.mjs flush` возобновляют попытки. Отдельной Windows-службы нет.
- Хранятся до 128 ожидающих сообщений и 4096 последних ключей подавления
  повторов. Во время повтора сохраняется UUID сообщения. Клиент Automesh
  подавляет повторное отображение этого UUID. Между получением квитанции и
  записью состояния есть окно сбоя: гарантия exactly-once не заявляется.
- Очередь привязана к отправителю, получателю и origin. Изменение назначения
  при наличии старых записей отклоняется, сообщения не пересылаются новому
  адресату автоматически.
- Один lock координирует hooks и MCP. Если процесс принудительно завершён,
  оставшийся lock требует проверки: закрыть плагин, убедиться, что записанный
  в `outbox.lock` PID больше не существует, удалить **только** этот lock и
  повторить отправку. Автоматического перехвата живого/сомнительного lock нет.
- Headless-контекст изолирован: не загружает код опубликованного сайта,
  хранит ключи только в памяти и проходит обычный подписанный challenge
  сигналинга. Для localhost отдельно разрешается доступ браузера к локальной
  сети. Политики сервера не ослабляются.

## Разработка и проверка

Из корня MeshAutonomy:

```powershell
node scripts/build-notifier.mjs
npm --prefix plugins/automesh-notifier test
node scripts/test-notifier-browser.mjs
```

Последняя команда создаёт два временных аккаунта и локальный сервер; проверяет
настоящий WebRTC, подпись, расшифрованный текст и квитанцию получателя.
Через `AUTOMESH_TEST_BROWSER` можно выбрать браузер для теста.
Исходники браузерного адаптера находятся в `browser/`, готовые автономные
сборки — в `dist/`. Не заменять ядро приложения другим форматом сообщений.
`python scripts/package-notifier.py` создаёт ZIP и проверяет отсутствие
локальных путей, личных адресов и файлов данных; включены лицензии встроенных
криптографических зависимостей в `THIRD_PARTY_NOTICES.md`.

Документация платформы:
[пакет и локальный каталог](https://developers.openai.com/plugins/build/plugins),
[hooks, поля Stop и доверие](https://learn.chatgpt.com/docs/hooks).
