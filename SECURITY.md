# Security policy

Experimental preview software. Internal checks do not replace an independent
security/cryptography audit. Do not rely on this preview for high-risk
communication or irreplaceable data.

Use **Security → Report a vulnerability** when private reporting is enabled.
If unavailable, request a private channel in an issue without exploit details
or secrets. No private contact address is invented here. Do not post seeds,
passwords, node master keys, deployment tokens, private QR invitations or chats.

Include build/version, platform/browser, boundary and reproducible steps using
disposable accounts. Redact identifying addresses, SDP/ICE, IPs and filenames.
Do not probe other users' accounts or production queues.

Client devices, peer identity, local storage, signaling, node authorization,
disk state, TLS/proxies and releases are separate boundaries. TLS does not
replace message encryption. GitHub provenance does not prove code is safe.
Same-user shared hosting is not isolation from compromised neighbor processes.

No bug bounty, response-time guarantee or formal support lifetime is offered.
Never disable TLS/SSH host checks or operating-system protection.
